GPU 选型建议

部署结论和“GPU推荐”行中出现的 H100、H200 仅为优选示例，不是唯一答案。可按以下路径筛选其他卡型；最终仍以框架兼容性和压测结果定型。

简单推算路径

  1. 先看精度与软件支持。候选卡、vLLM 和固定模型 revision 必须支持 BF16、Gated DeltaNet、Gated Attention 与目标输入形态；任一项不满足，直接排除。
  2. 再看显存能否装下一个副本。经济型的副本需求为 66.4GB；按 90% 有效显存换算，单卡标称显存至少需 73.8GB（66.4 ÷ 0.90）。H100 PCIe 80GB 因此可作为单卡示例候选，但仍只代表容量可行。
  3. 单卡不够时再定卡数与并行。峰值生产型的副本需求为 157.6GB；按 85% 有效显存换算，单卡需至少 185.4GB（157.6 ÷ 0.85）。H200 141GB 不满足单卡条件，示例中的 4 卡/副本仅在 vLLM 支持 TP=4、同副本互联满足时才成立；不能把任意多张卡的标称显存直接相加。
  4. 最后用压测确认。在可部署的 1–3 个方案中，验证 P95 TTFT、30 Token/s 目标、峰值显存和稳定性，选出满足目标且总卡数合理的方案。

精细推算路径

  1. 容量边界。以“权重 + KV/状态池 + 工作区”复核 66.4GB/157.6GB 的每副本需求，再按 90%/85% 有效显存换算候选卡。Gated DeltaNet 状态、视觉输入和更长上下文须通过压测上浮。
  2. 并行与互联边界。确定每副本卡数、TP/PP 切分和单节点容纳量。多卡 TP=4 重点核对节点内高速互联；若跨节点，还要核对 RDMA 和网络带宽。DP=2 是两个完整副本，不把显存合并为一个副本。
  3. 性能排序。在通过硬门槛的卡型中，优先比较 BF16 吞吐、HBM 显存带宽、Tensor Core 能力和互联带宽；CUDA Core、RT Core 等非主要推理瓶颈指标只作辅助参考。
  4. 工程与生命周期验证。核对卡型形态、功耗散热、服务器插槽/供电、驱动与 vLLM 版本、监控能力和备件可得性；以同模型版本、同长度和同并发压测结果定最终型号与卡数。

卡型先满足“精度/软件、可用显存、可实现的并行拓扑”三项硬门槛，再按性能、工程条件和压测排序；H100/H200 仅用于说明筛选后的优选结果。

估算过程

本节只解释资源配置表中的七类资源；GPU 型号由上节根据这些结果筛选，不在此重复估算。计算中出现的每一个数字均在“输入”中标明数值、单位、来源或采用理由。

1. 显存容量：保障权重、缓存与工作区驻留

输入：总驻留参数 27B（官方模型卡）；权重与 KV 均为 BF16，即 16 bit = 2 bytes；官方模型卡列出 16 个 Gated Attention 层、每层 4 个 KV Head、Head Dimension 为 256。普通 KV 下限因此为 16 × 4 × 256 × 2（K 与 V）× 2 bytes（BF16）= 65,536 bytes/Token；经济型为 8 个活跃请求、每请求 2,048 输入 + 512 输出 Token；峰值生产型为 32 个最大长度请求、每请求 32,768 输入 + 4,096 输出 Token。20% 余量（系数 1.20）用于未公开的 Gated DeltaNet 状态、视觉输入和运行工作区；该状态没有可核实的精确公式。

估算过程：

权重显存 = 27B × 16 bit ÷ 8 ÷ 1,000,000,000 = 54GB 经济型 KV = 8 × (2,048 + 512) Token × 65,536 bytes/Token ÷ 1,000,000,000 = 1.34GB 经济型每副本显存 = (54 + 1.34)GB × 1.20 = 66.4GB 峰值生产型 KV = 32 × (32,768 + 4,096) Token × 65,536 bytes/Token ÷ 1,000,000,000 = 77.3GB 峰值生产型每副本显存 = (54 + 77.3)GB × 1.20 = 157.6GB

术语备注：权重是加载到显存的模型参数；KV 是 Gated Attention 的请求上下文键值缓存，会随长度和并发增长；运行工作区是推理引擎的临时显存占用。Gated DeltaNet 维护线性注意力状态，不可直接按普通 KV 公式替代，需由框架支持并单独实测。

结果：经济型每推理副本至少需要 66.4GB 显存，峰值生产型至少需要 157.6GB；两者都是客观容量下限，不绑定任何卡型。特殊状态和视觉开销需在压测中验证是否需要继续上浮。

2. CPU：支撑分词、调度与请求预处理

输入：经济型为 1 GPU/节点、8 个活跃文本请求；采用每请求 1 vCPU 的 Tokenization/调度预算，以及 16 vCPU 的单 GPU 服务基线。峰值生产型为 4 GPU/节点、32 个活跃文本请求；采用 16 vCPU/GPU 的服务进程预算和 32 vCPU 的生产服务基线。不启用 CPU Offload；视觉预处理未计入。

估算过程：

经济型 vCPU = max(16 vCPU 服务基线, 8 请求 × 1 vCPU/请求) = 16 vCPU/节点 峰值生产型 vCPU = max(32 vCPU 服务基线, 4 GPU × 16 vCPU/GPU) = 64 vCPU/节点

术语备注：Tokenization 是文本与 Token 的转换；CPU Offload 是把部分模型或缓存放到内存，会显著增加 CPU 与内存需求。

结果：经济型配置 16 vCPU/节点，峰值生产型配置 64 vCPU/节点。纯文本低并发时可下调；视觉预处理或 CPU Offload 时必须按实际负载重新上调。

3. 内存：保障制品加载、缓存与运行时数据

输入：官方模型制品为 55.6GB；经济型采用 1.25 倍加载系数（1 份制品 + 25% 加载缓存）和 128GB 工程下限；峰值生产型采用 1.50 倍加载系数（1 份制品 + 50% 运行时/回滚元数据余量）和 256GB 工程下限。不启用 CPU Offload。

估算过程：

经济型内存 = max(128GB, ceil(55.6GB × 1.25)) = 128GB/节点 峰值生产型内存 = max(256GB, ceil(55.6GB × 1.50)) = 256GB/节点

术语备注：制品是可下载的模型文件集合；ceil 是向上取整函数，确保容量不足时按更大的整数容量配置。

结果：经济型配置 128GB/节点内存，峰值生产型配置 256GB/节点；该容量用于模型加载与运行缓存，不代表默认允许 CPU Offload。

4. 系统盘：承载系统、运行环境与日志

输入：经济型工程基线由操作系统 40GB、驱动/容器 30GB、日志与诊断 30GB 组成；峰值生产型采用操作系统 40GB、驱动/容器与运行环境 40GB、日志/监控/诊断 120GB。这些是本方案的工程预留，而非模型制品容量。

估算过程：

经济型系统盘 = 40GB + 30GB + 30GB = 100GB/节点 峰值生产型系统盘 = 40GB + 40GB + 120GB = 200GB/节点

术语备注：工程基线是为操作系统、驱动、容器、日志和诊断预留的最低容量，不包含模型制品。

结果：经济型配置 100GB/节点系统盘，峰值生产型配置 200GB/节点；系统盘承载运行环境和日志，不与模型盘或共享存储合并。

5. 模型盘：保存本地模型版本与回滚副本

输入：官方模型制品为 55.6GB；经济型本地保留 1 个版本，峰值生产型本地保留当前与回滚共 2 个版本；两档均采用 20% 安全余量，即系数 1.20。

估算过程：

经济型下限 = ceil(55.6GB × 1 版本 × 1.20) = 67GB，向上配置为 100GB/节点 峰值生产型下限 = ceil(55.6GB × 2 版本 × 1.20) = 134GB，向上配置为 200GB/节点

术语备注：制品是模型权重、配置和 tokenizer 等文件集合；ceil 是向上取整函数；回滚版本用于上线异常时恢复到上一可用版本。

结果：经济型配置 100GB/节点模型盘，可保留一个版本；峰值生产型配置 200GB/节点，可保留当前与回滚两个版本。模型盘不承载系统日志。

6. 共享存储：集中保存制品、配置与共享数据

输入：经济型集中保留 1 个 55.6GB 制品和 20% 余量（系数 1.20）；峰值生产型集中保留 2 个版本和相同余量，并额外预留 100GB 供共享配置、镜像缓存与压测数据。共享存储不按节点数重复相乘。

估算过程：

经济型共享存储下限 = ceil(55.6GB × 1 版本 × 1.20) = 67GB，向上配置为 100GB 峰值生产型共享存储下限 = ceil(55.6GB × 2 版本 × 1.20) + 100GB = 234GB，向上配置为 300GB

术语备注：共享存储由集群共同使用，不按节点数重复相乘；制品和回滚预留用于集中分发与恢复。

结果：经济型配置 100GB 共享存储；峰值生产型配置 300GB。单节点经济型在容量、IOPS、备份均满足时可与模型盘合并；峰值生产型为回滚和多节点一致性建议分离。

7. 公网带宽（用户接入）：承载用户请求与响应

输入：响应方式采用流式；经济型为 8 个活跃流、峰值生产型为 32 个活跃流，单请求输出速度均为 30 Token/s。纯文本响应按每 Token 4 bytes、协议与接口开销按 1.30 系数估算；吞吐换算使用 8 bits/byte 与 1,000,000 bits/Mbps。用户未提供入口/API 网关的典型或峰值到达 RPS，因此不将并发和请求时长反推值用于公网入向或总带宽。

范围说明：本项仅估算公网用户接入带宽，即用户到 API 网关或服务入口的南北向请求与响应。在实际部署中，还应注意：服务私网带宽用于网关、推理副本、存储等内部东西向通信，按部署拓扑单独核实；若同一推理副本采用跨节点 TP/PP，还需单独评估低时延高速互联与 RDMA 网络。二者均不纳入本公式。

估算过程：

流式经济型出向峰值 = 8 个活跃流 × 30 Token/s × 4 bytes/Token × 1.30 × 8 ÷ 1,000,000 = 0.010 Mbps 流式峰值生产型出向峰值 = 32 个活跃流 × 30 Token/s × 4 bytes/Token × 1.30 × 8 ÷ 1,000,000 = 0.040 Mbps 公网入向峰值 = 用户实测到达 RPS × 单请求输入字节 × 协议系数；本次缺少典型/峰值到达 RPS，故入向及公网用户接入带宽不输出数值。

术语备注：到达 RPS 是每秒新进入服务入口的请求数；流式输出持续传输增量 Token，出向按同时活跃流和每流 Token/s 计算。协议系数用于覆盖 JSON、TLS，以及 SSE/WebSocket 事件封装和心跳等非 Token 开销。

结果：经济型流式出向峰值约 0.010 Mbps，峰值生产型约 0.040 Mbps；两档公网入向与最终公网用户接入带宽均待补充入口监控的到达 RPS 后计算，不以并发或平均请求时长反推。

部署注意事项

  • 初始不要开放原生 262K 或 1M 上下文；先限制 65,536 Token，再逐步压测上调。
  • 思考模式、图片或视频会改变输出长度、显存、CPU 预处理和公网用户接入带宽，需要单独压测。
  • Gated DeltaNet 状态池需由目标框架支持并实测；Gated Attention 的 KV 计算只覆盖全注意力部分，二者合计才是显存规划依据。

压测与验收计划

  • 至少测试输入 2K/32K、输出 512/4K、并发 1/8/32、最大长度并发 1/32、思考开关和图片输入。
  • 验收 P95 TTFT、ITL、单请求 Token/s、Prefill/Decode 吞吐、峰值显存、错误率和长稳。
  • 若 H100 运行时显存超过 72GB，或多模态显存越界，改用更大显存 GPU、降低长度上限或验证量化制品。
