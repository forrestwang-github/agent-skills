# 证据来源与联网检索策略

本策略适用于模型、GPU、推理引擎、量化兼容性和性能基准。开始任何联网检索前必须完整读取。只有本策略允许的证据才能支撑配置结论。

## 1. 总原则

1. 搜索引擎、Agent 搜索结果和聚合页面只用于定位候选链接，不是证据。
2. 必须打开原始页面、原始文件、正式 PDF 或固定版本仓库。
3. 必须核实发布者身份、精确型号或 revision、发布日期/版本和测试条件。
4. 关键事实必须写入 `evidence[]`，记录发布者、来源类型、直接 URL、访问日期、revision、匹配等级及其支持的结论。
5. 找不到允许来源时，向用户索取资料或输出低置信度区间；不得用第三方数字补空缺。

## 2. 允许的数据源

### 2.1 模型结构、参数和制品

按以下顺序取证：

1. **官方模型制品**：模型发布者控制的仓库中，精确 commit/revision 下的 `config.json`、权重索引、制品清单、量化配置和自定义代码。
2. **官方模型仓库/模型卡**：发布者官方组织名下的模型卡、README、Release 和部署说明。
3. **官方技术报告**：从模型官方仓库或官方网站直接链接的论文、技术报告或白皮书。
4. **推理引擎官方实现资料**：仅用于核实该引擎实际读取的结构字段、特殊注意力、KV Cache 和算子实现，不能覆盖模型官方制品事实。

仓库身份必须满足至少一项：

- 从模型发布者官方网站直接链接；
- 位于发布者公开确认的 GitHub、Hugging Face、ModelScope 或其他官方组织账号；
- 仓库说明和发布者官方网站能够双向确认归属。

只写 `main`、`latest` 或模型简称而没有固定 revision 时，只能用于初步评估；正式交付前必须固定 commit、tag 或不可变制品版本。

### 2.2 GPU 固定硬件规格

只允许：

1. GPU 厂商官网发布的正式 Datasheet、Product Brief、规格页；
2. GPU 厂商官方开发者文档、架构白皮书、编程指南和互联文档；
3. GPU 厂商官方仓库中的固定版本规格或 Release；
4. 厂商正式发布公告，仅用于尚无正式 Datasheet 的新产品，并标记 `preliminary`。

GPU 型号、形态和显存版本必须完全一致。例如 PCIe、SXM/OAM、不同显存容量不能共用一条规格。正式 Datasheet 优先于产品页，产品页优先于发布公告。

云厂商实例页只能证明该云实例的配置，不能作为 GPU 芯片固定规格、可售性或性能的来源。

### 2.3 推理引擎与量化兼容性

只允许：

1. 引擎官方文档的版本化页面；
2. 引擎官方 GitHub/GitLab 仓库中的 Release、tag、代码和支持矩阵；
3. 模型发布者针对该引擎发布的官方部署指南；
4. GPU 厂商官方软件栈、驱动、编译器和算子支持文档。

必须绑定引擎版本、模型 revision、GPU/加速器、权重格式、KV Cache 精度和所需并行方式。“兼容 CUDA”“兼容生态”或营销性兼容声明不能证明具体模型可运行。

### 2.4 性能基准

允许两类：

1. **官方基准**：模型发布者、推理引擎项目或 GPU 厂商发布，且完整披露模型 revision、精度、GPU 型号/数量、引擎版本、TP/PP/DP、输入输出长度、并发/RPS和关键运行参数。
2. **可复现独立基准**：MLCommons/MLPerf 等公开规则基准，或同时提供测试代码、配置、硬件、软件版本和原始结果的独立测试。

客户现场压测可作为 `user_supplied` 证据，但必须记录测试环境和原始结果，不能冒充公开官方基准。

缺少任一关键条件时，最多标记 `similar`；只有理论 FLOPS/TOPS、显存带宽或营销吞吐时标记 `spec-only`，所有性能承诺字段必须为 `null`。

## 3. 明确禁止作为配置结论证据的来源

以下来源可以帮助发现线索，但不得进入最终 `evidence[]` 支撑确定性结论：

- 搜索结果摘要、搜索引擎自动答案和通用 AI 回答；
- 百科、参数聚合站、排行榜聚合页和未经发布者确认的数据库；
- 新闻媒体、自媒体、公众号、个人博客、论坛、问答和社交媒体帖子；
- 经销商、代理商、零售商和二手交易页面；
- 无法确认官方归属的 GitHub/Hugging Face/ModelScope 仓库或 fork；
- 没有原始 URL、版本、测试条件的截图、表格和转述；
- 云实例商品页中的芯片理论规格、库存、价格和区域信息；
- 未披露模型、精度、引擎、负载和拓扑的 Token/s、TTFT 或 ITL 数字。

## 4. 证据分类

`evidence[].source_type` 只能使用：

- `official_artifact`：官方模型配置、权重索引或制品；
- `official_documentation`：官方文档、规格页、技术报告或白皮书；
- `official_repository`：官方仓库中的固定 commit、tag、Release 或代码；
- `official_datasheet`：GPU 厂商正式 Datasheet/Product Brief；
- `official_benchmark`：测试条件完整的官方性能基准；
- `reproducible_benchmark`：测试条件、代码/配置和结果完整的独立基准；
- `user_supplied`：用户提供的配置或现场测试资料。

`publisher` 必须填写实际发布组织，不能填写搜索引擎、转载站或访问工具名称。

## 5. 冲突与降级

同一事实冲突时：

1. 精确 revision 的原始制品优先于模型卡和技术报告；
2. 正式 Datasheet 优先于产品页和发布公告；
3. 当前版本文档/代码优先于旧版本；
4. 同条件实测优先于相近条件外推；
5. 仍无法消除冲突时，同时保留证据和差异，置信度降为 `low`，输出范围而非单值。

用户资料与公开官方资料冲突时，不静默覆盖。分别列出差异，并要求用户确认实际部署制品或现场环境。

## 6. 搜索停止条件

1. 模型事实找到精确 revision 的官方制品后停止搜索同一字段。
2. GPU 规格找到精确型号/形态的正式 Datasheet 后停止搜索同一字段。
3. 性能依次搜索 exact 官方基准、similar 官方基准、可复现独立基准。
4. 上述三轮均无结果时停止，标记 `benchmark_required`，不得继续搜索第三方数字。

最终输出前逐项检查：每个模型关键参数、GPU 候选、引擎兼容结论和非空性能数字是否都有合格 `evidence_id`。
