五、资源估算过程

只解释资源配置表中的资源建议；GPU 型号是上一节基于这些结果筛出的候选，不参与本节公式。

显存容量

计算输入：27B BF16 权重、典型/最大 Token、并发、KV 下限和 20% 工作区。

权重 = 27B × 16 ÷ 8 = 54GB 经济型 KV = 8 × (2,048 + 512) × 65,536 bytes = 1.34GB 经济型基础量 = (54 + 1.34) × 1.20 = 66.4GB 生产型最大长度 KV = 32 × (32,768 + 4,096) × 65,536 bytes = 77.3GB 生产型基础量 = (54 + 77.3) × 1.20 = 157.6GB

结果与表格对应：资源表给出经济型 66.4GB/副本、峰值生产型 157.6GB/副本的基础显存门槛。特殊状态和视觉输入未量化，因此 GPU 候选还必须保留额外余量并压测。

CPU

计算输入：经济型单 GPU、生产型 2–4 GPU/节点、文本 Tokenization 与服务进程基线。

经济型 vCPU = max(16, 8 × GPU数/节点) = 16 生产型 vCPU = max(32, 16 × GPU数/节点)；4 GPU/节点时 = 64

结果与表格对应：资源表配置经济型 16 vCPU/节点、峰值生产型 64 vCPU/节点。仅纯文本低并发时可下调；视觉预处理或 CPU Offload 时应上调。

内存

计算输入：模型制品 55.6GB、运行时缓存、加载与回滚余量。

经济型下限 = max(128, ceil(55.6 × 1.25)) = 128GB 生产型下限 = max(256, ceil(55.6 × 1.50)) = 256GB

结果与表格对应：资源表配置 128GB/节点与 256GB/节点；这不是将模型常态 CPU Offload 到内存的容量承诺。

系统盘、模型盘与共享存储

系统盘：经济型 100GB；生产型 200GB 模型盘：经济型 ceil(55.6 × 1版本 × 1.2) = 67GB，配置 100GB 模型盘：生产型 ceil(55.6 × 2版本 × 1.2) = 134GB，配置 200GB 共享存储：按集中版本、回滚和共享数据预留；此例为 100GB / 300GB

结果与表格对应：系统盘承担系统与日志，不能与其他盘合并；经济型可酌情合并模型盘和共享存储，生产型分离以支持版本分发和回滚。

带宽

单请求时长 ≈ 2 + 512 ÷ 30 = 19.1 秒 典型 RPS ≈ 8 ÷ 19.1 = 0.42；峰值 RPS ≈ 32 ÷ 19.1 = 1.68 应用带宽 = RPS × (输入 Token + 输出 Token) × 4 bytes × 8 × 1.3 × 2

结果与表格对应：纯文本应用流量低于 1Gbps，资源表统一取至少 1Gbps；视觉输入或跨节点并行另行测算，示例生产型建议预留 10Gbps。

六、部署注意事项

  • 作用：说明本规划成立的边界，避免把默认输入误当成普遍结论。
  • 初始上下文限制为 65,536 Token；开放 262K/1M 前必须重算显存并压测。
  • 视觉输入、思考模式、量化和 Gated DeltaNet 状态会改变资源结论，应触发重新评估。
  • 框架、模型 revision 和镜像必须固定；更换任一项后，兼容性和性能证据失效。

七、压测与验收计划

  • 作用：把容量候选验证为可上线方案，而非重复解释理论。
  • 矩阵：输入 2K/32K，输出 512/4K，并发 1/8/32，最大长度并发 1/32，文本与视觉分开测试。
  • 监测：P95 TTFT、ITL、单请求 Token/s、总吞吐、峰值显存、错误率和长稳。
  • 决策：显存超出可用门槛则增加每副本卡数或降上下文；TTFT/吞吐不达标则调整卡型、并行度或副本数。

八、模拟数据与待证据项

  • 模型资料引用的是本线程的既有示例；GPU SKU、互联能力和候选结果均为模拟。
  • 正式运行时，skill 只对最终 1–3 个候选查官方 GPU 规格、框架兼容性和性能证据。
  • 没有同条件性能基准时，候选状态必须显示为 benchmark_required，不输出保证性 TTFT 或吞吐。
