# 阿里云账单分析

## 目标

使用确定性程序完成原始账单解析、字段映射、去重、金额计算、用量汇总、交叉校验和 Excel 生成。只把已验证的汇总事实交给模型解释。

生成：

1. 账单分析：按计费方式、产品和月份统计应付金额；
2. 后付费分析：按产品、计费项、地域、单位和月份统计用量与应付金额；
3. 趋势分析：展示月度费用、产品费用和后付费计费项趋势；
4. 数据说明：记录来源、行数、字段、重复、金额核对、警告和分析边界。

不要直接使用模型计算原始 Excel 或 CSV。

首次部署时安装依赖：

```bash
python -m pip install -r scripts/requirements.txt
```

## 选择数据入口

默认选择文件入口。只有客户不方便导出文件或需要补齐账期时，才选择 API 入口。

### 文件入口

收集：

- 客户账单文件或目录；
- 客户名称；
- 可选的起止月份；
- 是否需要合并多个资源购买账号。

支持 CSV、XLSX、ZIP 和包含多个月份文件的目录。要求客户导出计费项级明细；普通汇总账单不能替代计费项明细。

执行：

```bash
python scripts/analyze_bill.py file \
  --input "<账单文件或目录>" \
  --from "2026-01" \
  --to "2026-06" \
  --customer "客户名称"
```

未指定月份时分析文件中全部账期。包含当前未结束月份时允许生成报告，但必须保留部分月份警告。

### API入口

允许售后将客户提供的临时 AK/SK、客户名称和账期一次性粘贴到当前对话。不要求使用密码平台。

执行前：

- 确认 AK/SK 齐全；
- 只显示 AccessKey ID 末四位，不复述完整凭据；
- 使用账单只读权限；
- 不把凭据写入配置、中间文件、报告或普通日志。

执行：

```bash
python scripts/analyze_bill.py api \
  --ak "<AccessKey ID>" \
  --sk "<AccessKey Secret>" \
  --from "2026-01" \
  --to "2026-06" \
  --customer "客户名称"
```

任一月份拉取失败或产品汇总金额与计费项明细金额不一致时，不生成正式报告。执行结束后提醒客户禁用并删除本次临时 AK。

## 数据规则

- 使用`账单信息/费用类型`判断后付费、包年包月和其他费用；
- 不使用`账单信息/交易类型`代替计费方式；
- 使用产品Code和计费项Code作为分组键，名称只用于展示；
- 使用`应付信息/应付金额（含税）`作为消费金额；
- 用量和用量单位同时为空时保留金额、用量不按零处理；
- 不跨用量单位合计；
- 零金额和负金额不删除；
- 金额全程使用 Decimal；
- 原始文件保持只读；
- 任一行解析失败时停止生成正式报告。

字段和聚合口径见：

- 处理阿里云 V2 文件时读取 [references/bill-schema-v2.json](references/bill-schema-v2.json)；
- 核对费用类型时读取 [references/billing-type-map.json](references/billing-type-map.json)；
- 核对报表口径时读取 [references/report-schema.md](references/report-schema.md)；
- 指导客户导出文件时读取 [references/bill-file-guide.md](references/bill-file-guide.md)；
- 指导客户创建和回收凭据时读取 [references/ram-access-guide.md](references/ram-access-guide.md)。

## 质量门禁

正式报告必须满足：

- 指定账期完整；
- 原始非空行全部成功解析；
- 应付金额全部可解析；
- 没有无法解释的明细ID冲突；
- 没有未确认的多账号或多币种混合；
- Python Decimal 与 SQLite 分组汇总一致；
- 账单分析、后付费分析和趋势分析金额一致；
- Excel 回读总金额与分析结果一致。

失败时读取最后一行 JSON 中的 `validation_path`，向用户说明具体错误和修复方法，不声称分析已经完成。

## 模型边界

报告生成后，可以根据 `analysis-result.json` 概括主要产品、费用结构和明显趋势，但：

- 不重新计算金额；
- 不读取数万行原始明细进行推理；
- 不根据账单判断实例闲置；
- 不判断CPU或内存是否需要升降配；
- 不自动选择资源包规格；
- 不承诺节省金额；
- 不把趋势变化解释为确定的业务原因。

参考性观察必须标记“仅供参考，需要结合合同、产品定价、监控数据和业务情况确认”。

## 返回结果

命令最后一行是机器可读 JSON。

成功时读取 `report_path` 并将 Excel 发送到当前对话，同时简要说明：

- 分析账期；
- 记录数；
- 产品数；
- 数据质量警告；
- 当前月是否完整。

失败时不发送不完整报告。
