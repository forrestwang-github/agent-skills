# 阿里云账单分析 Skill 评审报告

评审日期：2026-07-17

## 总体结论

当前 Skill 的核心功能较完整，已经具备账单拉取、聚合分析和 Excel 报告生成能力，但在凭据安全、失败语义、目录卫生、跨平台兼容和 Skill 结构设计方面存在明显优化空间。

综合评价：**5/10，可运行原型，不建议未经整改直接分发或用于生产环境。**

## 高优先级问题

### 1. 不应要求用户在对话中提交 AK/SK

`SKILL.md` 当前强制要求用户直接提供长期凭据，并通过命令行参数传给脚本。即使入口脚本对自身日志做了脱敏，AccessKey Secret 仍可能出现在：

- 对话记录；
- Agent 工具调用记录；
- 系统进程命令行；
- 调试平台或异常日志。

建议：

- 首选阿里云 OAuth、MCP 或其他短期授权机制；
- 如果必须使用 AK/SK，只接受最小权限 RAM 子账号的临时凭据，不接受主账号 AK；
- 优先从 `ALIBABA_CLOUD_ACCESS_KEY_ID` 和 `ALIBABA_CLOUD_ACCESS_KEY_SECRET` 环境变量读取；
- 命令行 `--ak`、`--sk` 参数仅保留为兼容模式，避免在文档中推荐；
- 不在对话中收集或复述 Secret。

### 2. 单月失败后继续生成报告会产生误导

当前错误处理规则允许某个月份拉取失败后跳过该月，继续生成 Excel。对于财务数据，这会产生一份看似完整、实际缺失数据的报告。

建议：

- 默认任一月份失败即终止正式报告生成；
- 如果业务上需要部分结果，必须在文件名、最终回复和独立的“数据完整性”Sheet 中标明缺失月份；
- 增加原始记录金额、聚合金额、Excel 总计的交叉校验；
- 校验差异不为零时返回失败，不交付为正式报告。

### 3. 发布目录包含完整虚拟环境和运行产物

检查结果：

- `scripts/` 约 48.57 MB，共约 3130 个文件，主要来自 `scripts/venv/`；
- `output/` 包含 28 份历史 Excel；
- 存在意外嵌套目录 `scripts/E_/Codding/Claudecode_project/...`；
- 当前没有 `.gitignore`。

建议清理：

- 删除 `scripts/venv/`；
- 删除 `output/*.xlsx`；
- 删除意外嵌套路径；
- 添加 `.gitignore`，忽略虚拟环境、缓存、真实配置和输出文件；
- 发布包只保留 `requirements.txt`，由部署环境安装依赖。

建议的忽略项：

```gitignore
scripts/venv/
venv/
__pycache__/
*.pyc
output/*
!output/.gitkeep
config/config.json
```

### 4. 示例命令与实际目录结构不一致

`SKILL.md` 示例使用：

```text
venv/Scripts/python.exe scripts/bill_quoter_auto.py
```

但当前虚拟环境实际位于 `scripts/venv/`。项目文档还混合了 Windows 路径和 Linux/OpenClaw 路径，容易造成跨平台失败。

建议统一为：

```bash
python scripts/analyze_bill.py --from 2026-01 --to 2026-03
```

依赖环境由部署方管理，Skill 不携带或定位自己的虚拟环境。

## 中优先级问题

### 5. `SKILL.md` 职责过多

当前 `SKILL.md` 共 257 行，同时包含：

- 触发和交互流程；
- 完整报表字段定义；
- 时间解析规则及重复示例；
- OpenClaw、钉钉发送命令；
- 部署配置；
- 项目文件树；
- V1 归档说明。

建议将其压缩到约 100～150 行，只保留：

- 触发条件；
- 安全输入方式；
- 时间范围规则；
- 唯一入口命令；
- 成功与失败判断；
- 输出文件交付要求。

详细报表字段、聚合口径和完整性规则可迁移到 `references/report-schema.md`，按需读取。

### 6. 包含不必要的辅助文档

`docs/deployment-guide.md` 和 `docs/skill-introduction.md` 更接近 README 或项目说明，不是 Agent 执行任务所必需的内容。根据 Skill 的渐进披露原则，应避免在发布包中放置额外介绍、部署过程和开发归档文档。

`docs/get_aksk.docx` 当前用于指导用户创建并提交 AK/SK，也与安全整改方向冲突。建议替换为简短的最小权限 RAM 配置说明，且不引导用户在对话中发送 Secret。

### 7. 依赖特定 Agent 平台能力

当前指令写死了：

- `AskUserQuestion`；
- 钉钉连接器行为；
- `openclaw message send`；
- `/root/.openclaw/...` 输出路径。

这些能力并非通用 Codex Skill 接口，会降低可移植性。

建议使用平台无关的描述：

> 若缺少必要参数，向用户询问；生成后将准确的本次输出文件作为当前对话附件返回。

平台专属部署方式如需保留，应放在发布包外的部署文档中。

### 8. 正式入口和归档脚本过多

当前同时存在：

- `bill_quoter.py`；
- `bill_quoter_auto.py`；
- `bill_excel_generator.py`（V1，未使用）；
- `bill_excel_v2.py`；
- `debug_months.py`。

多个候选入口会增加 Agent 选错脚本和维护逻辑分叉的概率。

建议：

- 合并为一个正式 CLI，例如 `scripts/analyze_bill.py`；
- 将 Excel 生成器命名为稳定名称，不在正式文件名中使用 `v2`；
- 将 V1 归档和调试脚本移出发布包；
- 为正式入口定义稳定的退出码和机器可读输出。

### 9. 缺少 `agents/openai.yaml`

当前项目没有推荐的 Skill UI 元数据。建议增加：

- `display_name`；
- `short_description`；
- `default_prompt`。

这些元数据可以改善 Skill 在 Codex 中的展示、发现和默认调用体验，并应与 `SKILL.md` 的触发描述保持一致。

## 工程质量改进

### 参数和时间校验

- 校验月份必须符合 `YYYY-MM`；
- 校验开始月份不得晚于结束月份；
- 明确处理用户指定当前月或未来月份的行为；
- 将自然语言周期解析集中到一个函数并增加测试；
- 避免在 `SKILL.md` 中重复维护相同的月份计算示例。

### API 稳定性

- 增加限流和临时网络错误的指数退避重试；
- 区分鉴权失败、权限不足、限流、网络超时和服务端异常；
- 设置单页和单月超时；
- 记录请求 ID，便于定位阿里云 API 问题；
- 不在异常消息中输出请求签名或凭据。

### 输出文件确定性

`bill_quoter_auto.py` 当前在没有拿到 `FILE_PATH` 时，会查找目录中最新的 Excel 作为兜底。这可能把历史报告误发给用户。

建议：

- 每次运行生成唯一 `run_id`；
- 仅返回本次运行创建的绝对路径；
- 未拿到该路径时直接失败；
- 不使用“目录中最新文件”作为兜底。

### 自动化测试

建议至少覆盖：

- 单月与跨年月份范围；
- 空账单；
- 多页分页；
- 重复记录；
- 未知产品代码；
- 单月失败和重试；
- 部分月份失败；
- 金额与 Excel 总计一致性；
- Sheet 名、公式范围和图表数据源。

### 依赖管理

当前 `requirements.txt` 只有：

```text
openpyxl>=3.1.2
```

建议设置经过验证的兼容范围，例如：

```text
openpyxl>=3.1.2,<4
```

并在 CI 或发布验证中固定 Python 主版本。

### 编码兼容

本地语法检查通过，但 Windows 下执行 `--help` 时中文显示出现乱码。建议：

- 所有文本文件统一保存为 UTF-8；
- 子进程调用明确指定 UTF-8 编码；
- 在 Windows 控制台环境验证中文 stdout 和 stderr；
- 避免依赖宿主 PowerShell 的默认代码页。

## 检查结果说明

- Python 脚本语法检查通过；
- 没有调用真实阿里云 API；
- 没有读取或展示配置文件中的凭据值；
- 官方 `quick_validate.py` 未能完成，因为本机校验环境缺少 `PyYAML`，因此不能视为已通过完整结构校验；
- 当前目录未识别为 Git 仓库，无法通过 Git 状态确认哪些输出或配置文件会被提交。

## 建议整改顺序

1. 改造 AK/SK 输入和传递方式；
2. 将单月失败改为严格失败或明确的部分结果；
3. 清理 `venv`、历史输出和意外嵌套目录；
4. 增加 `.gitignore`，保护真实配置；
5. 合并为一个正式入口；
6. 精简 `SKILL.md`，拆分详细参考资料；
7. 增加 `agents/openai.yaml`；
8. 补充完整性校验和自动化测试；
9. 验证 Windows、Linux 下的安装、中文编码和输出交付流程。
