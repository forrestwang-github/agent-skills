# 结构示例

只在不确定结构深度或证据呈现方式时读取。示例用于说明模式，不限制真实主题的章节数量。

## 示例一：只知道一个技术名词

用户：“我只听说过 PagedAttention，帮我系统学一下并沉淀到知识库。”

建议主线：

```text
一句话定义与学习目标
→ 它要解决的 KV 缓存内存碎片问题
→ 必要前置：连续批处理与 KV 缓存
→ 逻辑块到物理块的映射机制
→ 两个请求分配、增长和释放的逐步实例
→ 为什么它提高有效容量与批处理机会
→ 映射开销、块大小选择和不适用边界
→ 与操作系统分页、前缀缓存的区别
→ 相关概念、自测问题、来源
```

若用户没有提供资料，研究应从原始论文、项目官方文档与实现材料开始，不应停下来要求附件。

## 示例二：因素分析

用户：“哪些因素影响大模型首词元延迟？帮我找出优先优化项。”

建议主线：

```text
指标定义：请求到达至首个输出词元可见
→ 收益与质量边界
→ 因果链：排队 → 调度 → 预填充计算 → 通信 → 输出传输
→ 候选因素筛选（数量由链路覆盖决定）
→ 关键因素：机制、证据、边界、动作、验证指标
→ 按依赖与投入回报排序的实施路线
→ 相关机制知识链接与自测问题
```

候选表中的每项都要有因果路径和证据强度。采样温度若不影响首词元产生前的链路，应明确排除；若某实现提前执行采样相关初始化，则应说明实现条件，不能把结论绝对化。

## 示例三：来源和推导

正文写法：

```markdown
在版本 X 的官方实现中，块大小为可配置项，而不是协议固定常数。[S1]

若每个词元的缓存占用为 B 字节、块含 T 个词元，则单块占用为 `B × T`。当 B 来自模型结构计算、T 来自当前配置时，可以据此估算单块内存；该结果是推导值，不是官方基准。[S1][S2]
```

来源写法：

```markdown
- [S1] **官方配置文档**｜项目维护团队｜官方文档｜版本 X  
  URL：<https://example.com/config>  
  检索日期：YYYY-MM-DD  
  支撑：块大小可配置及其参数语义。
```

关键点是把直接事实和计算结论分开，让未来读者与检索系统都能恢复推理链。
